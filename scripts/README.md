# Обучение и проверка моделей

Команды ниже выполняются из корня проекта. Нужен Python 3.11+; на Linux для LightGBM также нужна системная библиотека `libgomp` (например, пакет `libgomp1` в Debian/Ubuntu).

```bash
python3 -m venv model/.venv
source model/.venv/bin/activate
python -m pip install -r scripts/requirements-training.txt
python scripts/train_models.py --check-only
python scripts/train_models.py
python scripts/check_models.py
```

В Windows окружение активируется командой `model\.venv\Scripts\activate` в cmd или `model\.venv\Scripts\Activate.ps1` в PowerShell. Скрипты определяют корень проекта по своему расположению и работают из любого текущего каталога.

## Датасеты

Parquet-файлы не входят в Git. До запуска подготовьте датасеты с признаками и целевыми столбцами, которые используют существующие программы обучения:

| Модель (`--models`) | Файл внутри `model/dataset/parquets/` | Целевой столбец | Дата |
|---|---|---|---|
| `fire_risk` | `fire_risk/fire_risk_dataset_v3_equipped.parquet` | `is_incident` | `ts` |
| `nsd_event` | `unac/unac_dataset_v2.parquet` | `is_nsd_clean` | `ts` |
| `nsd_risk` | `unac/unac_risk_dataset.parquet` | `is_nsd_day` | `day` |
| `fault_risk` | `fault_risk/fault_dataset_v2.parquet` | `will_fail_next_24h` | `day` |

Для поломок также нужен столбец `ид_объект`. Полные списки признаков находятся в `model/models/*/scripts/train_model*.py`. Датасеты риск-моделей должны содержать данные до 2024 года для обучения и начиная с 2024 года для оценки, с обоими классами в каждой части. Генерация этих Parquet из сырых CSV в общий скрипт не входит.

`--check-only` проверяет наличие непустых файлов и установленных Python-модулей, не загружая датасеты и не проверяя их схему. Ошибки содержимого и загрузки библиотек обнаруживаются при обучении.

## Выбор моделей и путей

```bash
python scripts/train_models.py --models nsd_event nsd_risk
python scripts/train_models.py --data-root /path/to/parquets --output-root /path/to/models
python scripts/check_models.py --model-root /path/to/models
```

По умолчанию последовательно обучаются все четыре модели. Используется тот же Python, которым запущен общий скрипт. Результаты сначала записываются во временный каталог; только после успешного завершения всех выбранных программ и проверки наличия артефактов они копируются в `model/models/*/saved/`, заменяя одноимённые файлы. Графики также сохраняются. Ошибка обучения не меняет прежние артефакты; само финальное копирование нескольких файлов не является атомарной операцией.

Для проверки используются модель, порог и список признаков каждой из четырёх моделей: `check_models.py` проверяет загрузку, диапазон порога, наличие `predict_proba` и согласованность количества признаков. Это не оценка качества и не проверка совпадения расчёта признаков с онлайн-сервисом. Загружайте только доверенные `.joblib`.

Программы сохраняют исходную методику: пожар и событийный НСД используют случайный стратифицированный сплит, риск НСД и поломки — временной. Порог подбирается на оценочной выборке; её метрики не являются независимой финальной оценкой. Для пожара существующий скрипт также использует дополнительные статистические признаки, которые онлайн-сервис пока не рассчитывает (при инференсе они заменяются нулями).

Модель поломок выбирается среди RandomForest, CatBoost и LightGBM, поэтому CatBoost включён и в зависимости сервиса для загрузки возможного победителя. После обучения пересоберите и перезапустите ML-контейнер:

```bash
docker compose -f backend/docker-compose.yml --profile model up -d --build model-service
```

Проверка логики общего запуска без датасетов и ML-библиотек:

```bash
python3 -m unittest discover -s scripts -p 'test_*.py'
```
